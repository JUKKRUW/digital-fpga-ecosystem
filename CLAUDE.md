# Digital FPGA Ecosystem — notes for working on this repo

Teaching toolchain for the EDGE Spartan-7 (XC7S15) board: draw gates → simulate → pick pins → build.
UI text is Thai; code and comments are English.

## Layout
| Path | What |
|---|---|
| `schematic&bus2vhdl.html` | **Schematic Studio**, the gate editor. One self-contained HTML file (opens from disk and from the launcher). ~12k lines of editor + an inlined UX layer at the end. |
| `editor/ux/*.js`, `editor/ux/ux.css` | **Source of the UX layer** (save chip/timeline, browser sim, truth-table tool, generators, welcome/templates, stepper, pin page, problem markers, Ctrl+K, …). Inlined into the HTML by `editor/build.py`. |
| `editor/ux/12-wire-tidy.js` | Wire tidy: re-routes paths from the connection list (🧹 sheet / selected net, Debug panel "แก้ให้"), the 🧲 ratsnest placement mode (straight coloured lines per net → "จัดสายให้"), and moving a part re-routes only the branches off it (`wtAfterMove`, called from the core mouseup/nudge). |
| `editor/ux/13-sheet-order.js` | Drag a sheet in the project tree to reorder it (the order = key order of `schematics`, rewritten in place; saved, undoable). |
| `editor/ux/14-part-truth.js` | Inspector ▸ "📋 ดูตารางความจริง" for the selected part: copies it onto a scratch sheet (an IN per input pin, an OUT per output) and runs the browser simulator (`clientCombSim`). |
| `editor/ux/15-jk-counter.js` | Tools ▸ "ตัวนับ/หารความถี่ JK-FF" (and MCP `generator.kind=jk_counter`): synchronous JK-FF mod-N from the excitation table + K-map (`jkCounterIntent`, self-checked), placed like the lab sheet (`jkLayout`) and routed by 12-wire-tidy. The intent vocabulary now includes `JKFF` (pins j/k/clk/rst/pre, q/qn) and `block:<sheet>` (pins = the sheet's port names). Also `dividerIntent` (Tools ▸ หารความถี่, MCP `generator.kind=clock_divider`): ÷ any N as a binary counter + synchronous clear, 50 % duty for even N. |
| `editor/ux/16-rt-sim.js` | Real-time board sim (sim page ▸ "⚡ เล่นเวลาจริง (50 MHz)" when a port is mapped to the board clk): `rtCompile` turns the flattened sheet into nets + evaluators and runs it event-driven (BUFs merged, ripple clocks in delta steps; same results as the stepped `clientSeqSim`, checked in `tests/editor/rt-sim.spec.js` on `tests/fixtures/lab6_digital_counter.schproj.json`). LEDs / 7-seg are averaged per frame (persistence of vision, jittered samples); switches incl. bus bits and push buttons act live. |
| `editor/ux/17-bus-ports.js` | Bus ports for generated circuits: `busifyPorts(sch, which)` turns numbered IN/OUT groups (q0..q3) into one bus port with split/merge BUSTAPs placed where the old port pins were, then routes only the new nets. MCP `build_circuit {bus}` / `make_bus_ports`, Tools ▸ รวมขาเป็นบัส (refused for a sheet another sheet already uses as a block). |
| `editor/ux/18-ai-agent.js` | The chat's **เอเจนต์** mode: the local model (llama-server `--jinja`, Qwen3.5 / Typhoon) calls the MCP tools itself (`mcp_server.AGENT_TOOLS`, schemas + argument checks from `/api/agent/tools` / `/api/agent/normalize`, model via the launcher proxy `/api/llm/chat`), each step shown in the chat, a nudge to check+simulate before answering; runs logged to `<config>/agent-runs/*.jsonl`. MCP `ai_model` / `ai_chat` / `ai_chat_status` let Claude drive the chat and read every step (to test the AI feature). Tested with a scripted fake model in `tests/llm.spec.js`. |
| `editor/ux/19-module-library.js` | The Modules tab (cross-project library in localStorage `schstudio.modules`) over MCP: `list_modules` / `save_module` / `use_module` / `open_module` / `delete_module`. A module now stores `deps` (every sheet it uses as a block, recursively) and they are adopted together; before, a module's sub-blocks were lost. |
| `editor/ux/20-one-project.js` | In the app a project folder holds ONE project: a `.schproj.json` saved into a project folder is reduced to the active project (`uxProjectOnlyJson`, applied by `launcher/web/shim.js` and MCP `save_project`), and `?open=` / MCP `open_project` load only the project named like the folder from an older multi-project file (`uxProjectFromFile`). |
| `editor/ux/21-build-into-bus-bits.js` | `build_circuit {sheet}` (new name = that sheet, an empty sheet is filled, one with parts refused) and `connect` to one bit of a bus pin (`y.i[2]`, `s.o[3]` → merge / split BUSTAP placed for you). |
| `editor/ux/22-parts.js` | **Part library** `PARTS` (MCP `build_part` / `list_parts`): adders, subtractors, comparator, mux/demux, decoder, encoder, BCD→7seg, parity, majority, counters, divider, shift register, register, toggle, edge detector, debounce. Each kind is generated by code AND checked against a reference model (all rows ≤10 input bits, else 300 vectors; sequential parts clock by clock against a state model) before it is drawn; the sheet gets `sch.verified` (`sheetVerifyStamp`, dies with the next edit via `sheetHash`). `tests/editor/parts.spec.js` builds every kind. |
| `editor/ux/23-formula-verify.js` | `build_circuit {formula}` (equations → truth table, `formulaTable`), `verify_truth_table {formula}` + `independent` (an expectation equal to what the sheet was built from = `sch.builtFrom` does not count) + `recognized` (`uxRecognize`), `save_module` refuses unverified sheets unless `force`, and the agent's fast path (`partFromMessage` / `aiagFastPath`: a part it can name is built with no model call). Equations also take `xnor` / `⊙`, `nand`, `nor` (Thai เอ็กซ์นอร์ / แนนด์ / นอร์ in 34). build_circuit refuses a drawing over `MCP_MAX_DRAW` (100) parts: routing a 10-input table froze the page for minutes, with every MCP call (even `ai_chat_stop`) stuck behind it; `globalRoute` keeps its A* state in typed arrays and stops its passes / polish on a time budget. `ai_chat_stop` and `get_events` run beside other ops (`MCP_WAITING_OPS`). |
| `editor/ux/24-parts-ui.js` | The part library in the Modules tab: grouped list above "โมดูลของฉัน", a form per part (size / bus / options, ports preview) → วางเป็นบล็อก on the sheet on screen (free spot) or เปิดเป็นแผ่นใหม่; the user's modules carry ✓ ตรวจแล้ว / ยังไม่ได้ตรวจ. |
| `editor/ux/25-spec.js` | **Acceptance tests**: `sch.spec` (formula / table / clock sequence) re-checked after every edit (`specRun`, debounced on snapshot/undo; a formula is checked port by port by `specFormulaMismatches`, so bus ports are numbers: `{cout,sum} = a + b + cin`, `a[2]`, `s[0] = …`), ✓/✗ badge in the project tree, a box in the Inspector (nothing selected) with a form incl. "ใช้สิ่งที่วงจรทำตอนนี้"; a pass stamps the sheet verified. MCP `set_spec` / `check_spec` (also the agent's; its prompt says set the spec from the request first). |
| `editor/ux/26-fsm.js` | **FSM designer** (Tools ▸ ออกแบบ FSM, MCP `build_fsm`): a few lines of text (`inputs: x`, `state S0: z=0`, `S0 -> S1 when x`, `else`, Mealy `/ z=1`, `reset S0`) or an object → binary encoding (reset = 0), minimised next-state/output logic (unused codes → reset), D-FFs; checked clock by clock against the diagram (`fsmVerify`) before it is drawn. Live diagram (SVG) + state table in the dialog; `sch.fsm` kept and used as the sheet's acceptance test. |
| `editor/ux/27-report.js` | **Lab report** (Tools ▸ ทำรายงานแลป, MCP `make_report`): every sheet (top first, then its blocks) as SVG, ports, truth table + minimised equations or 16 clocks, FSM diagram, spec, pin table, VHDL → `<proj>_report.html` in the project folder (print to PDF) + a .doc for Word. |
| `editor/ux/28-lab-helper.js` | **Lab helper** (Tools ▸ ผู้ช่วยทำแลป): the lab sheets from `ai/rag/labs/*.json` (launcher `/api/rag/labs`) as a checklist per item (progress in `project.labProgress`), buttons that prefill the agent / Q&A chat, "ตั้งเป็นข้อกำหนด" when the solution states plain equations (`labhFormula`, all-or-nothing), and the solution folded as a hint. |
| `editor/ux/29-board-doctor.js` | **Board doctor** (ลงบอร์ด page ▸ 🩺, MCP `board_check`): `boardDoctor(sch)` finds unmapped / shared pins, wrong direction, active-high 7-seg on the common-anode display (swept over the truth table vs `SEG7`), no `an` driven, clock from a push button, raw 50 MHz on a small counter, plus `explainSim` errors. "เทียบกับบอร์ด" preview: toggle the mapped switches → LEDs and digits (active-low) via `mcpEvalOuts`. |
| `editor/ux/30-wire-hints.js` | **Wiring hints** (Inspector 💡 + dashed guides for the selected part, MCP `suggest_wires`): `wireHints(sch)` for unconnected pins only — blocks of one type in order chain `x_out→x_in` (cout→cin), block input ← sheet INPUT of the same name (only shared signals like clk/rst/en when several blocks have that pin), `a2` / bit 2 of bus `a` → the block labelled …2, sheet OUTPUT ← a unique unused block output of that name / index. Applied through `MCP_OPS.connect` (undo works). |

## Workflow

## How the UX layer hooks in
The editor defines everything as top-level functions/consts in one classic `<script>`. The UX layer is a second
`<script>` that **wraps globals by reassignment** (`snapshot = function(){ … _snapshot.apply(this, arguments) … }`),
so the editor's own internal calls go through the wrapper. Rules:
- Don't declare a top-level name the editor already uses (a `const` clash kills the whole UX script — this happened with `STEP`).
- Files load in name order (`01-…` → `07-…`); a later file may wrap or reassign what an earlier one defined.
- Sheets carry optional extras that serialize with the project: `sch.pinmap` (port/bit → board target, keyed by the
  VHDL port name `sanId(name)` / `name[i]`) and `sch.portOrder` (declared IN/OUT order for generated sheets).

## Releasing
1. Bump `VERSION` in `launcher/app.py`, commit, merge to main.
2. `.github/workflows/release.yml` sees the new `VERSION` on main, tags `vX.Y.Z` and calls `build-windows.yml`, which builds
   Setup.exe + portable zip and attaches them to a GitHub Release. (A tag pushed by hand still works too; the build fails
   if the tag and `VERSION` disagree.)
3. Installed copies see the new release on their next start (launcher update check) and can update in place;
   projects (Documents) and settings (%APPDATA%) are untouched.

## Not in the repo
Vivado/ISE, `*.lic`, LLM models (`ai/models`, `ai/llama`), GHDL, course PDFs — see README. The RAG index
(`ai/rag/index.jsonl`) is not in git either: `build_windows.ps1` builds it into every installer, and the launcher builds it
on first use when missing (`rag_search` → `/api/rag/search`, MCP `search_course`, the agent's up-front course notes). Semantic side: with the optional Qwen3-Embedding 0.6B
(`llm.EMBED`, in `models/embed/`) a second llama-server runs CPU-only (`--embedding`, on a free port); document vectors are cached
in the data folder and fused with BM25 by reciprocal rank (`rag_search` → `mode: hybrid`).
