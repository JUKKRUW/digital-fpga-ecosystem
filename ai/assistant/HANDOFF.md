# HANDOFF — ผู้ช่วย AI ถาม-ตอบ (ไทย · RAG · ความจำ · เขียน/อธิบายโค้ด · รันในเครื่อง)

เอกสารส่งต่องานสำหรับ session ถัดไป อ่านไฟล์นี้กับ `CLAUDE.md` ที่ root ก่อนเริ่ม
กติกาของ repo ยังใช้ตามเดิมทุกข้อ:

- commit ในชื่อ laplacian-n ไม่มี trailer หรือ footer ของ Claude
- คุยกับเจ้าของเป็นภาษาไทย
- แก้ `editor/ux/*` แล้วต้องรัน `python3 editor/build.py`
- ข้อความที่ใช้เป็นข้อมูลฝึก ให้เขียนด้วยโมเดล open-weight เท่านั้น
- key ของ OpenRouter ห้ามเข้า repo

## 1. เจ้าของต้องการอะไร

> "ไหน ๆ ก็ไม่ได้ใช้ agent แล้ว ฉันอยากได้ AI ตัวที่ถามตอบเก่ง ๆ ต่อ RAG ต่อ memory
> เขียนโค้ดได้ อธิบายได้ พูดไทยได้ รันบนเครื่องฉัน เป็นแอปแบบ Ollama อะไรเงี้ย"

แปลเป็นงานได้ดังนี้:

1. **ถาม-ตอบให้เก่ง**
   - ตอบได้ทั้งความรู้ digital logic / VHDL / FPGA และวิธีใช้โปรแกรม
   - ตอบยาวได้เมื่อคำถามต้องการ และค่อย ๆ แสดงคำตอบขณะพิมพ์ (stream)
2. **RAG**
   - ค้นเนื้อหาวิชาได้อยู่แล้ว
   - เพิ่มให้ค้นเอกสารของผู้ใช้เอง และแผ่นวงจร / VHDL ในโปรเจกต์ที่เปิดอยู่
   - บอกที่มาของสิ่งที่ตอบ
3. **Memory**
   - จำเรื่องที่ผู้ใช้บอกไว้ข้ามบทสนทนา เช่น ชื่อ กลุ่มแลป บอร์ด เรื่องที่ยังไม่เข้าใจ หรือวิธีที่ชอบให้อธิบาย
   - จำบทสนทนาเก่าได้
   - ผู้ใช้ดู แก้ และลบสิ่งที่ AI จำไว้ได้
4. **เขียนและอธิบายโค้ด**
   - เขียน VHDL ได้ และ **ตรวจก่อนตอบ** ด้วยตัวจำลอง VHDL ที่มีในแอปแล้ว
   - อธิบายโค้ดหรือวงจรที่ผู้ใช้วางหรือเลือกไว้ได้
   - Python / C ทั่วไปตอบได้ แต่ไม่มีตัวตรวจ
5. **ภาษาไทยต้องดี**: ไม่มีตัวจีนปน ไม่สลับภาษากลางประโยค
6. **รันในเครื่อง**
   - ไม่ส่งข้อมูลออกนอกเครื่อง ใช้ได้แบบออฟไลน์
   - ติดตั้งง่ายเหมือน Ollama คือกดดาวน์โหลดโมเดลแล้วใช้ได้เลย

**สิ่งที่ไม่ทำ:** โหมดเอเจนต์ (AI สั่งเครื่องมือ MCP แก้วงจรเอง) เลิกพัฒนาแล้ว ซ่อนได้แต่อย่าลบโค้ด
เพราะ dataset และ eval ยังอ้างถึงอยู่

## 3. ข้อเสนอสถาปัตยกรรม

```
editor chat (โหมด "ถาม-ตอบ")  ──►  launcher /api/assistant/chat  (ใหม่, SSE stream)
                                      │ 1 ประกอบ context: system + memory ที่ตรง + notes (RAG) + บริบทแผ่น/โค้ดที่เลือก
                                      │ 2 เรียกโมเดล: backend = llama-server ของแอป (ค่าเริ่มต้น) | Ollama | OpenAI-compatible อื่น
                                      │ 3 ถ้าคำตอบมี ```vhdl → vhCompile/vhRun (ส่งกลับไป editor ตรวจ) → แนบ ✓/✗ + error
                                      │ 4 หลังตอบ: สกัดสิ่งที่ควรจำ (json_schema) → memory store
                                      ▼
                         <data dir>/assistant.sqlite  (conversations, messages, memories, docs, vectors)
```

### 3.1 Backend ของโมเดล ("แอปแบบ Ollama")

- **ค่าเริ่มต้น: llama-server ที่แอปดูแลอยู่แล้ว** ตัวติดตั้งรวมไว้ให้แล้ว ผู้ใช้ไม่ต้องติดตั้งอะไรเพิ่ม
- **เพิ่มทางเลือก Ollama**: Settings ▸ โมเดล AI ▸ "ใช้ Ollama ที่ติดตั้งไว้"
  - endpoint `http://127.0.0.1:11434/v1/chat/completions` เป็นแบบ OpenAI-compatible
  - รายชื่อโมเดลอ่านจาก `GET /api/tags`
  - เหมาะกับผู้ใช้ที่มี Ollama อยู่แล้ว
- เขียน adapter เดียว (`ai/assistant/backend.py`) ที่ทุกที่เรียกใช้
- ตรวจให้แน่ใจว่า Ollama ส่ง `response_format` (json_schema) ได้จริง ถ้าส่งไม่ได้ ใช้ `format` แบบ native ของ Ollama แทน

### 3.2 เลือกโมเดล (ห้ามเดา ให้วัดผล)

ผู้สมัครที่ควรวัด ต้องเช็กรุ่นล่าสุดบน Hugging Face ก่อน เพราะรุ่นเปลี่ยนเร็ว:

- **Qwen3.5 9B** มีใน `CATALOG` แล้ว ตอนนี้ถือว่าเก่งสุดในเครื่องการ์ดจอ 6 GB ขึ้นไป
- **Typhoon 2.5 (Qwen3 4B)** มีในแค็ตตาล็อก ภาษาไทยดีสุดในกลุ่มขนาดเล็ก
- Typhoon หรือ OpenThaiGPT รุ่นที่ใหญ่กว่า ถ้ามี GGUF
- Gemma 3 12B
- Qwen3.5 4B SFT2 (ฝึกกับแอปนี้) **ใส่ไว้เป็นตัวเทียบเท่านั้น ไม่คาดว่าจะชนะ**
  - ข้อมูลฝึกส่วนใหญ่เป็นบทสนทนาของเอเจนต์: เรียกเครื่องมือ ตอบสั้นเป็นข้อความธรรมดา ไม่คิดก่อนตอบ temperature 0.3
  - ฝึกให้ทำงานแคบลง เสี่ยงลืมความรู้ทั่วไปและการเขียนโค้ดที่โมเดลตั้งต้นเคยมี
  - ขนาด 4B มีความรู้ในตัวน้อย
  - ถ้าโมเดลทั่วไปที่ใช้กับ RAG แล้วยังพลาดเรื่องเฉพาะวิชา ค่อยพิจารณาฝึก LoRA สำหรับถาม-ตอบโดยเฉพาะทีหลัง (ข้อมูลจาก `gen_qamode.py` และคำตอบที่ผู้ใช้กด 👍) ไม่ใช้ตัว SFT ของเอเจนต์

**วิธีวัด:**

1. ใช้ `tools/dataset/eval_qamode.py` กับคำถามชุด hold-out
2. เพิ่มชุดคำถามใหม่ 3 ชุด
   - เขียนหรืออธิบาย VHDL ตรวจด้วย `vhdl_check.js`
   - คำถามที่ต้องใช้ความจำ (ถามต่อจากที่เคยบอกไว้)
   - คำถามที่ต้องอ่านเอกสารผู้ใช้
3. วัดเวลา (tokens/s) บนเครื่องเจ้าของด้วย

ผลออกมาแล้วให้ตั้งรุ่นที่ชนะเป็นค่าเริ่มต้นของโหมดถาม-ตอบ แยกจากโมเดลของเอเจนต์

**ต้องถามเจ้าของก่อนเลือก:** การ์ดจอรุ่นอะไร มี VRAM กี่ GB และมี RAM เท่าไร

### 3.3 RAG ที่ขยาย

1. **เนื้อหาวิชา**: ใช้ `rag_search` เดิม
2. **เอกสารของผู้ใช้** (ใหม่)
   - โฟลเดอร์ `Documents/…/AI Notes` หรือปุ่ม "เพิ่มเอกสาร" รับ .pdf / .md / .txt / .vhd
   - ตัดเป็นชิ้นด้วย `ai/rag/pdf_extract.py` และวิธีตัดชิ้นเดิม
   - embed ด้วยโมเดล embedding ตัวเดิม เก็บใน sqlite
3. **บริบทโปรเจกต์**
   - แผ่นที่เปิดอยู่: ports, netlist สั้น, spec และ VHDL ที่ `exportVhdl` สร้าง
   - บล็อก VHDL ที่เลือกอยู่
   - ส่งไปเฉพาะเมื่อคำถามพูดถึงวงจรของฉัน / แผ่นนี้ / โค้ดนี้ (ตัด token)
4. **แสดงที่มา**: ใต้คำตอบแสดงชิปที่มา เช่น "บทที่ 8 · Lab 7 · ไฟล์ xxx.pdf" กดเปิดดูได้

### 3.4 Memory

ตารางใน sqlite:

- `memories(id, text, kind[fact|preference|todo], source_msg, created, last_used, pinned, vec)`
- `conversations(id, title, summary, created)`
- `messages(conv_id, role, content, created)`

**การเขียน:**

- หลังตอบแต่ละครั้ง ให้โมเดลตัวเดิมสกัดสิ่งที่ควรจำออกมา
  - บังคับรูปแบบด้วย `response_format: json_schema` เป็นรายการ `{text, kind}` หรือรายการว่าง
  - ทำแบบนี้แล้วเชื่อถือได้ (วิธีเดียวกับ `aiagStructuredCall` ในไฟล์ 49)
- ถ้าผู้ใช้พิมพ์ "จำไว้ว่า …" ให้บันทึกทันที
- ข้อความที่ซ้ำหรือขัดกับของเก่า (embedding ใกล้กันมาก) ให้แทนที่ของเก่า

**การอ่าน:**

- ดึง memory ที่เกี่ยวข้อง k = 5 ด้วย hybrid search แบบเดียวกับ RAG
- ใส่สรุปบทสนทนานี้ลงใน prompt
- ใส่ข้อความล่าสุด N ข้อความเต็ม ๆ ข้อความเก่ากว่านั้นใช้สรุปแทน

**ให้ผู้ใช้คุม:**

- หน้า "สิ่งที่ AI จำ" ใน Settings มีรายการ แก้ / ลบ / ปักหมุด และสวิตช์ปิด memory
- มีปุ่มบทสนทนาใหม่
- ทั้งหมดอยู่ในเครื่อง

### 3.5 เขียนโค้ด + ตรวจ

- เลิกห้าม markdown ในโหมดนี้: ให้หน้าแชตแสดง markdown และ code block (มีปุ่มคัดลอก และปุ่ม "วางเป็นบล็อก VHDL" ซึ่งเรียก `vhdlBlockSave` ได้เลย)
- โค้ด VHDL ในคำตอบให้ editor ตรวจด้วย `vhCompile`
  - ถ้าคอมไพล์ไม่ผ่าน ส่ง error กลับให้โมเดลแก้ 1–2 รอบก่อนแสดง (self-repair)
  - แสดงผลเป็น ✓ คอมไพล์และจำลองผ่าน / ⚠ ตัวจำลองไม่รองรับ (เช่น port map) / ✗ พร้อมบรรทัดที่ผิด
- ถ้าคำถามบอกพฤติกรรมไว้ชัด (เช่น "ตัวนับ 0–9") ให้ใช้ oracle เดิม (`oracleDerive`, ไฟล์ 36) สร้างตัวทดสอบแล้วรันเทียบ
- ข้อห้ามจากรอบก่อน (ไฟล์ 51 / 58) ยังใช้: ห้ามอ้างว่า "ตรวจแล้ว" ถ้าไม่ได้ตรวจจริง

### 3.6 ภาษาไทย

- system prompt ภาษาไทยฉบับใหม่ที่ยาวกว่าเดิม
- เปิดให้คิดก่อนตอบได้ (สวิตช์ "คิดก่อนตอบ") แต่ซ่อน `<think>` และแสดงเป็น "กำลังคิด…" ที่พับเก็บได้
- ใช้ `aiagScrubLang` กับคำตอบ และวัดอัตราคำตอบที่มีตัวจีนปนใน eval

## 5. ข้อควรระวัง

- **RAM / VRAM**
  - รอบก่อนเคยทำเครื่อง 24 GB เต็ม (ดูคอมเมนต์ `DEFAULT_ARGS` ใน `llm.py`)
  - memory กับ RAG เพิ่ม context ตั้ง budget token ของแต่ละส่วนให้ชัด
  - อย่าเพิ่ม `-c` ถ้ายังไม่ได้วัด
- **โหมดเรียบง่าย (สอบ)** ปิด AI ทั้งหมด (`68-simple-mode.js`) ผู้ช่วยตัวใหม่ต้องถูกปิดด้วยเหมือนกัน
- **ความเป็นส่วนตัว**: memory และเอกสารอยู่ใน data dir ของผู้ใช้เท่านั้น ห้ามส่ง telemetry
- **API ที่ใช้อยู่แล้ว**: `/ask` เดิมต้องยังใช้ได้ เพราะ dataset และ eval เรียกใช้อยู่ ให้ทำ `/api/assistant/chat` เป็น endpoint ใหม่แยกต่างหาก
- ห้ามแก้ schema ของ `AGENT_TOOLS`

## 6. คำถามที่ต้องถามเจ้าของ

1. เครื่องที่จะใช้มีการ์ดจอรุ่นไหน VRAM กี่ GB และ RAM เท่าไร
2. มี Ollama ติดตั้งอยู่แล้วไหม อยากให้ใช้ Ollama หรือให้แอปจัดการโมเดลเองเหมือนเดิม
3. ผู้ช่วยตัวนี้อยู่ในหน้าแชตของ Schematic Studio หรือเป็นหน้าต่างแยกเปิดจาก Home
4. อยากให้จำอะไรบ้าง และมีเรื่องที่ห้ามจำไหม
5. เอกสารของตัวเองที่อยากให้ค้นมีอะไรบ้าง (สไลด์ ชีตแลป โน้ต)
